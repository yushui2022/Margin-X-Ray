# 达人调查 Agent

用户刷到一条推荐，复制 TikTok 达人主页，希望查明这个人关联过哪些具体商品、发生过哪些有据可查的问题，以及结论的依据。已有 500 个账号构成发现目录。目录外的公开账号可以通过用户名或主页链接发起同样的调查，报告有独立地址，可以再次打开。

## 从一条链接到一份报告

| 环节 | Agent 做的事 | 用户能核对的依据 |
| --- | --- | --- |
| 识别账号 | 统一主页链接与用户名。用户点 Run research 后，服务端按用户名请求 TikHub，拿到账号的 secUid 再取一页最多 15 条公开帖子。逐条核对作者并去重。公开 embed 是备用来源。 | 返回账号、原帖链接、采集日期、实际数据来源、可用的发布时间及采集限制。 |
| 找关联商品 | 从文案识别明确的商业披露。若文案同时出现档案内的品牌或别名及具体产品词，则关联原帖和可能的商品页面。多种包装作为备选规格保留。 | 文案原文、原帖、候选商品页。新品牌和只有画面里出现的商品目前需要人工识别。 |
| 找独立证据 | 读取已发布的商品档案和带日期的监管初筛记录。遇到已知美国食品样本、匹配到其产品名，或帖子明确给出校验通过的商品条码，会按评分窗口检索 openFDA 食品召回数据库。每次最多 3 个查询。 | 公开查询链接、日期、召回记录编号（如有），区分候选命中、未检索到和来源不可用。 |
| 审核证据 | 研究人员先约定样本选择方法，再逐件确认达人关系、具体型号、市场、批次和事件时间，记录所有入样商品的核查结果。将完成复核的记录加入版本化审核档案。 | 选样方法、每个商品的结论、发布机构、一手材料链接、严重度判定说明。 |
| 出分并解释 | 规则引擎按当前版本计算问题指数和证据覆盖度。可选 AI 从已计算事实中选择最有解释力的一两项，由服务端生成英文介绍。无密钥、超时或回复不合规时也有规则说明。 | 指数、分项、窗口、版本、证据来源和待补项；每个数字均可复算。 |

公开简介、粉丝数和帖子可帮助核对身份。一次公开文案取样只能说明本次取得了什么。私密账号或不可用来源会显示采集受限。短视频正文、音频、完整带货历史与私有订单数据超出当前采集范围。

## 两种数值各自回答的问题

**Onion Score** 回答“这批已审商品中，有文件证实的问题有多频繁、多严重”。沿用项目的 `product-issues-v1`，范围 0–100，高分表示样本内问题更频繁或更严重。当前版本的事件窗口是 2025-11-18 至 2026-11-17。后续窗口应通过发布新版本更新，保留旧报告的计算依据。

- 至少 3 件不同的达人关联商品，每件都有来源、明确的审核结论和一致的选择方法。仍有未解决事项时显示 Pending review。
- 频率贡献为 70 × 有确认问题的商品数 ÷ 已审商品数。严重度贡献为 30 × 每件商品最高严重度系数之和 ÷ 已审商品数。轻微、中等、严重、危急分别取 0.25、0.5、0.75、1。每项取一位小数后相加。
- 算例：一个虚构样本审核 3 件商品，其中 1 件有已确认的中等问题，另外 2 件有明确的无已知问题审核记录。频率贡献 23.3，严重度贡献 5.0，合计 28.3。完全审核且未发现已记录问题的样本可以得到 0 分。
- 准入证据包括监管结论、官方召回、最终裁判、可追溯检测和已记录的卖方确认或处理。公开文案、价差、群众投票及品牌名搜索命中只用于引导调查。现有审核档案与准入规则分别在 [审核记录](../research/creator-issue-reviews.json) 和 [规则](../research/creator-issue-rubric.json)。

**Evidence Score** 回答“这份报告收集到了多少可以复核的材料”。沿用 `evidence-v3` 的十项检查。新账号可以先从身份匹配与公开文案获得覆盖分。已有档案按源合并和去重，人工选入的商业线索、有来源的商品规格与标价可按规则贡献分数。资料覆盖分和用户投票都不会改写问题指数。

## 服务端行为

浏览器只向同源服务请求任务状态和报告。GET 可以安全打开共享链接，POST 才会发起采集。同账号并发请求合并，队列、额度和最近成功报告存入 SQLite。刷新失败仍可读上次报告。成功报告默认复用 24 小时。进程正常退出会交还运行中的任务，异常中断的任务在租约到期后可重新领取。来源侧限时、有限次重试、全局并发和额度分别处理上游故障和调用成本。

| 设置 | 用途 |
| --- | --- |
| `TIKHUB_TOKEN` | 服务端 TikHub Bearer Token。缺省可尝试 TikTok 的公开 embed。 |
| `CREATOR_AI_API_KEY`、`CREATOR_AI_MODEL` | 一起配置时启用 AI 辅助选取解释事实；浏览器不接触凭据。 |
| `CREATOR_AI_BASE_URL` | 可选、兼容 Chat Completions 的服务端 API 根地址，默认 `https://api.openai.com/v1`。 |
| `CREATOR_RESEARCH_DB` | 研究数据库路径，默认 `data/creator-research.sqlite`。投票仍存于原有数据库。 |
| `CREATOR_RESEARCH_DAILY_LIMIT`、`CREATOR_RESEARCH_CLIENT_LIMIT` | 滚动 24 小时全服务的新任务上限，默认 100；单个直连地址每 10 分钟的新任务上限，默认 10。反向代理下该计数会合并同一代理的请求。 |

本地入口为 `npm run build` 后运行 `npm run preview`。达人页提供 Creator research 入口，目录外可直接输入完整用户名或主页链接。已接受的档案按版本随应用载入，更新审核记录后需重启本地服务并重建静态目录。已保存报告保留当次版本和采集日期，在下一次可刷新时更新。

接口参考见 [TikHub 主页](https://docs.tikhub.io/186826057e0)、[TikHub 帖子](https://docs.tikhub.io/186826058e0) 和 [openFDA 食品召回检索](https://open.fda.gov/apis/food/enforcement/how-to-use-the-endpoint/)。
